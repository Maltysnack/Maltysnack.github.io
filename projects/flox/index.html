Project

Flox

A small language for flow networks. You write nodes and arrows, and it simulates how something moves through them over time. Every example on this page is live: edit the program and the output reruns.

What it is

One grammar, three simulators. A mode line picks the physics: water through rivers and dams, probability through a Markov chain, or current through a grid that balances itself. The declarations, the arrows and print are the same in all three.

Underneath is a real three-stage interpreter, a scanner, a parser and a tree-walking evaluator, in about two thousand lines. It is a sketching tool for the shape of a system, not a hydrology engine or a power-flow solver, and it makes no forecasts.

The second worked example is a grid. compare runs one network under several scenarios side by side, here asking what happens if the main plant trips, or the tie line between the two cities is cut.

With the plant out, supply no longer meets demand and that column never settles. Add a scenario that sheds load to match the backup: "Shed load" with disable Plant with NorthCity.supply = -15 with SouthCity.supply = -15.

River flow

The default mode. Each river has a base flow, a peak multiplier that turns rainfall into a surge, and a decay for how much of that surge carries into the next day. Rainfall is given per day in millimetres. Flows add where rivers meet, and an outlet keeps a running total.

A dam stores what comes in and releases it at one of two rates. It holds back at its normal rate until storage crosses the threshold, then opens. Here the first storm fills it on day two, it runs open through the second, and closes again once it has drained.

Raise the dam's capacity to 60 and it never reaches the threshold; the town sees a much flatter week.

Markov chains

In markov mode the arrows carry probabilities, and the weights leaving each state must sum to one. Mass starts where start puts it and is redistributed every tick until nothing moves. Cycles are fine; a state that points to itself is absorbing.

The example is a footballer in the final third deciding whether to pass again or shoot, with a shot converting about one time in ten. The chain answers how possessions end in the long run.

Change Shoot -[0.10]-> Goal to 0.15 and Miss to 0.85. The final split follows the conversion rate; the pass weights only change how long it takes to get there.

Grammar

mode river|markov|grid;Picks the simulator. River if absent.
system Name;Starts a system. Everything after attaches to it.
A -> B -> C;A chain of edges, weight 1. A -[w]-> B sets a weight; <- points the other way.
river Name { ... }base and peak required, decay optional (0 to 1, default 0.7).
dam Name { ... }capacity in ML, threshold as 80% or 0.8, normalRate and openRate in ML/day.
outlet Name;Collects everything that reaches it.
node Name { supply: n }A generic state. In grid mode, supply is positive for generators and negative for loads, and must sum to zero.
start Name mass;Markov only: initial probability mass.
print Name n;Runs it. River: n mm of rain on day 1, or [r1, r2, ...] per day. Markov and grid: tick budget.
compare Name n as ...;Scenarios side by side, each "Label" with disable X or disable A -> B.
list Name; map Name;Lists the nodes and their edges, or draws the network.
